Install

Getting your signature into your mail client

Build your signature first, then use Copy signature for a rich paste, or Export HTML where a client wants raw source. Which one you need depends on the client — each guide below says so.

Before you start: if your signature includes a logo, make sure it is set from a hosted URL rather than an upload. Uploaded images are embedded as data, which Gmail and Outlook both strip — the signature will install fine and then show a broken image to everyone who receives it.

Outlook 365

Partial rendering
  1. In the editor, click Copy signature.
  2. Open Outlook and go to Settings → Mail → Compose and reply.
  3. Under Email signature, paste into the editing box with Ctrl+V.
  4. Give the signature a name, then choose whether it applies to new messages, replies, or both.
  5. Click Save, and send yourself a test message to confirm.
Expect two differences here. Outlook renders mail through Microsoft Word, which ignores border-radius — circular icon badges will arrive as squares. It also does not display inline SVG, so icons need to be hosted images to appear at all. Everything else — layout, spacing, colour, links — comes through intact.

Gmail

Good support
  1. In the editor, click Copy signature.
  2. In Gmail, open Settings → See all settings → General.
  3. Scroll to Signature and click Create new. Give it a name.
  4. Paste into the signature box with Ctrl+V.
  5. Set the defaults for new mail and replies, then click Save Changes at the bottom of the page.
Watch for the size limit. Gmail truncates signatures over roughly 10,000 characters, and an embedded logo will blow past that on its own. A hosted image URL keeps you far below the limit. Gmail also strips background images, so avoid relying on one for contrast.

Apple Mail

Full support
  1. In the editor, click Copy signature.
  2. Open Mail → Settings → Signatures.
  3. Choose the account on the left, then click + to add a signature.
  4. Clear the placeholder text, then paste with Cmd+V.
  5. Untick Always match my default message font — leaving it on strips your typography.
The best case of the four. Apple Mail has the most capable rendering engine, so rounded badges, spacing and colour all appear exactly as designed. If a signature looks right here but wrong elsewhere, the other client is the problem.

Yahoo Mail

Good support
  1. In the editor, click Copy signature.
  2. Open Settings → More Settings → Mailboxes.
  3. Select your address and toggle the signature on.
  4. Paste into the signature box with Ctrl+V.
  5. Changes save on their own — send yourself a test to confirm.
Yahoo removes style blocks. Anything defined in a <style> tag is discarded on send. Every rule in a Signvel signature is already inline, so nothing is lost here.

Thunderbird

Full support
  1. In the editor, click Export HTML and copy the source — this client wants raw HTML, not a rich paste.
  2. Open Account Settings and select your account.
  3. Tick Use HTML under the signature field.
  4. Paste the exported source and close the dialog.
Renders through Gecko — the same engine as Firefox, so CSS support is close to a browser. Rounded badges and spacing survive intact.

Proton Mail

Good support
  1. In the editor, click Export HTML and copy the source.
  2. Open Settings → All settings → Identity and addresses.
  3. Edit your address and enable the signature.
  4. Switch the signature box to code view, then paste.
Remote content is sanitised. Recipients may be asked to allow images from your address the first time, so a hosted logo can appear blocked until they do.

Google Workspace — organisation-wide

Admin required
  1. In the editor, click Export HTML and copy the source. This route needs raw HTML, not a rich paste.
  2. Open the Google Admin console → Apps → Google Workspace → Gmail.
  3. Select Compliance, then find Append footer.
  4. Choose the organisational unit the signature should apply to.
  5. Paste the exported HTML, then save. Changes can take up to 24 hours to propagate.
Appended footers behave differently. They are added by the server on send, so they appear once at the bottom of the thread rather than under each reply, and staff cannot edit or remove them. Personal details like a direct line have to come from per-user signatures instead — most teams run both.
